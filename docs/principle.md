# 方案：门禁卡复制

## 一、原理：刷一次卡，到底发生了什么

读卡器持续发射 13.56MHz 载波给卡供电，卡靠「负载调制」把数据回传。卡里只有三样东西：

| 组成 | 是什么 | 能不能复制 |
| --- | --- | --- |
| UID | 出厂唯一序列号，4 / 7 / 10 字节 | 能，写进 UID 可写卡 |
| 数据块 | 扇区里的内容（房号、权限、余额） | 能，前提是知道密钥 |
| 密钥 | 每个扇区的 Key A / Key B | 不能凭空得到，只能试/破解 |

门禁系统认卡，一般分三档：

1. **只认 UID**：最老的一批系统，读 UID 查白名单。复制 UID 就能进。
2. **UID + 数据**：还要校验某几个块的内容（比如 1 扇区的房号）。
3. **双向认证**：CPU 卡 / DESFire，卡和读卡器互相验密钥（DES/3DES/AES），卡里是加密文件系统。

所以「复制」也分三层，成功率依次下降：

- **UID 复制**：买 UID 可写的空白卡（CUID/FUID/Gen2），把 UID 写成一模一样
- **全卡复制**：MIFARE Classic 1K 共 16 扇区 × 4 块，逐扇区认证、读出 1KB、写进 magic 卡
- **逻辑复制**：CPU 卡做不到，除非拿到系统密钥（那就不是「复制卡」而是「破解系统」了）

## 二、为什么手机经常做不到

1. **HCE 模拟不了 MIFARE Classic。** 安卓的 Host Card Emulation 只能按 AID 响应 ISO-DEP 指令，而 Classic 用的是私有 Crypto1 握手，没有 AID 可谈。手机没法「假装」成一张 Classic 卡。
2. **厂商钱包的模拟是另一套东西。** 小米钱包的门卡模拟靠 NFC 控制器/SE 里的专用模拟模式，把 UID 和数据存进去再回放，只支持**未加密**的 Classic 卡。
3. **加密扇区没有密钥就是读不出来**，读不出来就没有数据可写。
4. **125kHz 的 ID 卡**（厚白卡、钥匙扣）频率都不对，手机 NFC 完全读不到。

结论：手机能当「读卡器 + 写卡器」，但当不了「破解器」，也当不了「加密卡」。

## 三、流程

```
① 鉴定卡型（5 分钟，不花钱）
   ├─ 小米钱包门卡模拟 → 成功 = 未加密 Classic → 直接用手机
   ├─ 提示加密 → 走 ②
   └─ 读不到 → 125kHz ID 卡 / 位置不对 → 停

② 读卡（MCT）：看 UID 长度、ATQA、SAK
   ├─ 4 字节 + SAK 08/18 → MIFARE Classic 1K/4K
   ├─ 7 字节 + SAK 00    → Ultralight / NTAG
   ├─ 7 字节 + SAK 20/28 → DESFire / CPU 卡 → 停，找物业
   └─ 读不出             → ① 的位置问题或 ID 卡

③ Classic 卡：试密钥
   ├─ 字典能开全部扇区 → dump → 写 CUID 卡 → ④
   └─ 有扇区开不了 → nested/hardnested
        ├─ 手机跑通（看运气）→ dump → 写卡 → ④
        └─ 跑不通 → Proxmark3 → ④
④ 刷卡验证
   ├─ 刷开 → 完成
   └─ 刷不开 → 滚动码 / CPU 伪装 / 系统绑定 → 只能找物业
```

## 四、能不能开发一个工具

能，但要分清工具在链路里补的是哪一段。手机 NFC 的射频访问只能由**安卓 App** 完成，所以工具分三档：

### A 档：DSH 侧脚本工具（不碰射频）

在手机上跑 Node 脚本，处理「卡数据」这一层：

- 解析 MCT 导出的 dump（`.mfd` / `.eml` / `.json`），校验长度、扇区结构、访问位
- 判断卡型（UID 长度 + SAK + ATQA 组合）
- 生成/合并密钥字典（`.keys` 文件），按常见厂商前缀排序
- 检查 dump 是否完整（哪些扇区缺、哪些块是空的）
- 出「写卡清单」：哪个块写什么、UID 怎么改
- 维护读卡记录、对比两次 dump 找滚动码

**今天就能交付，零依赖，纯 Node。** 缺点：写卡动作还得靠 MCT。

### B 档：安卓原生 App（能碰射频）

Kotlin 写，`NfcAdapter` + `MifareClassic` + `NfcA.transceive`：

| 功能 | API | 可行性 |
| --- | --- | --- |
| 读 UID / ATQA / SAK | `Tag` + `NfcA` | 稳 |
| 字典试 Key A/B | `authenticateSectorWithKeyA/B` | 稳，速度受限制 |
| 读全卡 dump | `readBlock` × 64 | 稳 |
| 写普通块 | `writeBlock` | 稳 |
| 写 magic 卡 UID | `NfcA.transceive`（Gen1a 后门 `40 43`，Gen2 直写块 0） | 看卡型 |
| 破解加密扇区 | nested / darkside / hardnested | 不稳，新机型时序受限 |

开发成本：Android SDK + JDK 约 1.2GB，本机 proot 能装；debug 签名出 APK；安装要你手动允许一次「未知来源」。MVP（读卡 + 试密钥 + dump + 写卡）**2–4 天**。

注意：`MifareClassic` 这套 API 在 Android 15 上还算稳，但 hardnested 要精确到微秒的时序，手机 NFC 栈大概率跑不出来——这就是为什么加密卡最终还是要 Proxmark3。

### C 档：硬件桥（真正能破加密卡）

Proxmark3 Easy（¥150 左右）+ 电脑，或者 PN532（¥60）。工具形态是封装 `pm3` 命令的脚本：一键 hardnested、一键写 magic 卡、读 125kHz。这是唯一能稳定处理加密 Classic 和 ID 卡的方案。

### 不能做的

- 做一个 App 让手机变成加密门禁卡（HCE 协议层面就不支持）
- 纯软件破解 CPU 卡 / DESFire 密钥
- 用手机读 125kHz 卡

## 五、建议

1. 先花 5 分钟做「① 鉴定」——它决定后面所有事，而且免费
2. 是未加密 Classic → 小米钱包直接模拟，收工
3. 是加密 Classic → 先跑 A 档工具把数据结构摸清楚，再决定值不值得上 B/C 档
4. 是 CPU 卡 → 别折腾了，找物业加卡

## 合规

只对自己有权使用的卡操作。复制他人门禁卡、绕过门禁系统可能触犯法律，也违反小区/公司的规定。
